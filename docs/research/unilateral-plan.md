# 單側動作支援：現況盤點與設計方案

目標動作：分腿蹲、保加利亞分腿蹲、弓步、登階、單腿 RDL、單臂啞鈴划船、單臂滑輪動作、單臂肩推、單側腿推／腿伸／腿彎舉。本文件只做診斷與設計；產品行為沒有改變（`node tests/regress.mjs` 輸出 IDENTICAL）。原型為 [`tools/research/unilateral-prototype.mjs`](../../tools/research/unilateral-prototype.mjs)（粗略的平面玩具模型，只用來估量級與暴露假設，不是產品程式）。

## 1. 結論摘要

- 左右對稱不是單一開關，而是**四層**結構性假設：(a) 姿勢只有右側關節＋單一矢狀面軀幹軸；(b) 外力與重量以「半身」為單位，`pose.barW`（兩側合計負重／體重）與其 `/2` 約定出現在 `biomech.js` 內約 74 行；(c) 地面／支撐反力只解矢狀面，額狀面用「力線通過髖」封閉；(d) 肌肉只有右側一份，軀幹只有 `erec`、`ra` 兩條、只對矢狀面伸屈出力。畫面左側是右側的鏡像。
- 單側動作新增三類物理：**左右不同的肢體姿勢與支撐**、**三維接觸力分配**（含水平向的成對力封閉）、**軀幹額狀面／水平面力矩與其肌肉**。
- 比較三案：A 全身雙側求解；B 右側模型加邊界條件；C 分階段混合（A 為架構、B 為第一階段）。**推薦 C**：先做不改既有數字的基礎建設與「單肢等效」動作（單側腿伸／腿彎舉／腿推），再依序做分腿站姿、軀幹三維＋單臂動作、單腿站立。
- 對既有 72 項（69 可選＋3 規劃中）的數值影響：**設計上為零**——舊路徑原樣保留，新求解器以「對稱不變量測試」在 69 項上逐項重現舊的半身結果後才可用於單側動作。
- 最大的科學風險不是程式，而是封閉假設：分腿站姿的前後腳**水平力成對（內部擠壓）**會讓前後腿髖力矩改變數倍（見 §5），目前沒有查到可直接採用的數值，只能作為明示的模型假設並附敏感度。

## 3. 單側動作需要的新物理

以下由 §5 原型估量，並對照文獻（§9）。

1. **左右不同的肢體與支撐。** 分腿站姿兩腳在不同位置甚至不同高度（保加利亞：後腳在凳上）；登階、單腿 RDL 的支撐腿與擺動腿完全不同；單臂動作另一手可能撐在凳面。
2. **三維接觸力分配。** 接觸點 ≥ 3 個且不共線（雙腳＋一手撐凳）時，垂直力由力與力矩平衡唯一決定；接觸點只有兩個時，重心必須落在連線上（姿勢要用側移去達到）；接觸點 ≥ 4 或兩腳分腿站姿的前後水平力成對，則是**靜力學不定**，必須有封閉假設（§5.1）。
3. **軀幹三個方向的力矩。** 單側負重或偏心的肢體重量在 L5 產生側屈（額狀面）與軸旋（水平面）力矩（原型：站姿單手 20 kg 於 x = 0.28 m，額狀面約 55 N·m；對稱雙啞鈴為 0）。需要三維軀幹方向（至少側傾與軸旋兩個新自由度）與對應的肌肉。
4. **額狀面髖負擔。** 單腿站立時，重心必須移到支撐腳上方；髖外展需求取決於骨盆側移與軀幹側傾（原型：骨盆置中時約 66 N·m、約 0.88 N·m/kg；HAT 向支撐側偏移 6 cm 降到約 40 N·m）。這個量在雙腳動作被「力線通過髖」封閉消去，單腿動作必須真的求出。

## 4. 方案比較

### 方案 A：全身雙側求解

每個單側動作的姿勢同時給出 `pose.R` 與 `pose.L` 與三維軀幹方向；力以側別標籤（`R/L/mid`）收集；每側肢體各自求力矩與肌肉；軀幹用兩側共同的三維求解。對稱動作退化為既有結果。

- **新增自由度：**軀幹側屈、軀幹軸旋（相對骨盆）、骨盆側傾與側移（單腿站立）、對側肩帶／手臂／腿的獨立姿勢。
- **接觸與平衡：**通用三維接觸求解器（接觸點集合＋垂直力＋水平力封閉）；`systemComZ` 擴成三維重心；`balanceCm` 增加左右分量。
- **肌肉：**所有肢體肌肉左右各解；軀幹需加側別（`erec` 左右分開），腹斜肌（外／內）因軸旋方向可分而加入；腰方肌是否獨立見 §6 的決策點（T28 原則：只加力學上分得出來的）。
- **顯示：**`pose.L` 取代鏡像；肌肉／關節圈左右分色；數據表加左右欄。
- **既有 72 項：**對稱動作保留舊路徑或以 `pose.L = mirror(pose.R)` 進入新路徑；對稱不變量測試保證等價。
- **驗證改動：**新增雙側求解器對稱等價測試、鏡像不變量、單側平衡殘差檢查。
- **工作量：**最大（見 §7）；`analyze` 約 280 行需先拆出可重用的肢體／肌肉求解函式。
- **風險：**重構面積大；軀幹與髖外展肌肉資料不足（§8）。

### 方案 B：保留右側模型，對單側動作加外力邊界條件

右側 = 「工作側」，沿用全部現有程式；另一側只以外力（對側手撐凳的反力、後腳的垂直力、擺動腿重量）進入軀幹平衡。只算工作側肌肉。

- **新增自由度：**軀幹側屈、軸旋仍須新增（否則單臂動作與單腿站立沒有意義）；骨盆側傾同上。
- **接觸與平衡：**對側以預設比例（例如「後腳承擔 x %」）當輸入；只對工作側求髖／膝／踝。
- **肌肉：**只右側；軀幹側屈／軸旋肌肉仍要左右區分，否則求解會把「對側肌」錯算成同側——這是 B 的結構缺陷：額狀面與水平面力矩的肌肉是**左右不同方向**的，單側肌肉集合無法表達。
- **顯示：**無法顯示對側肌肉活動，後腳（保加利亞後腿）與支撐腿全程不算。
- **既有 72 項：**幾乎不動（新增旗標）。
- **工作量：**較小（A 的約 1/3）。
- **風險：**後腿、對側軀幹肌肉都缺席；對側負重比例成為隱藏的輸入，容易被誤認為輸出；單腿站立時支撐腿就是工作腿但擺動腿重量與骨盆需求仍要處理。能解的只有「單肢等效」動作（見 C 階段 1）。

### 方案 C（推薦）：以 A 為架構、分階段交付，第一階段用 B 的做法

- 階段 0 做不改數字的基礎（側別標籤、三維軀幹方向、通用接觸求解器、`analyze` 拆分），以對稱不變量測試鎖住。
- 階段 1 先交「單肢等效」動作——單側腿伸、腿彎舉、腿推：這些動作的物理本來就是單肢的（座椅承受身體），對側不參與；結果等於現有半身結果在負重加倍後的值，風險最低，也能先驗證換邊、左右分色與介面。
- 後續階段才引入分腿站姿、軀幹三維、單腿站立（見 §6）。
- 比較表：

| | A | B | C |
|---|---|---|---|
| 分腿蹲後腿、對側肌肉 | 有 | 無 | 階段 2 起有 |
| 軀幹側屈／軸旋肌肉 | 左右分開 | 無法正確表達 | 階段 3 起有 |
| 交付時程 | 最晚（一次全部） | 最早 | 最早交付階段 1，其餘逐步 |
| 對既有 72 項風險 | 重構期有 | 低 | 低（每階段回歸 IDENTICAL） |
| 重工 | 少 | 單腿站立、單臂需整個改寫成 A | 少（階段 1 的單肢等效不會被推翻） |

## 5. 原型結果（`tools/research/unilateral-prototype.mjs`）

粗略的矢狀面／額狀面玩具模型（男 1.75 m、75 kg；de Leva 節段；軀幹直立；符號慣例未整理，只看量級）。

### 5.1 分腿蹲：前後腳負重與水平力封閉

站距 0.75 m、髖高 0.62 m、槓 = 1.0 體重、軀幹直立，兩腳只有垂直力時：

| 前腳垂直力份額 | 前腿髖力矩 (N·m) | 後腿髖力矩 (N·m) |
|---|---|---|
| 0.60 | 241 | −241 |
| 0.84 | 114 | −114 |

軀幹直立時前後腿髖力矩大小相等、方向相反（兩腿在同一個髖交會，軀幹上的重力線通過髖），只由靜力學無法分配。加入前後腳**成對水平力 H**（前腳向後、後腳向前）後：

| 前腳份額 | H = 0 | H = 0.15 BW | H = 0.30 BW | H = 0.45 BW |
|---|---|---|---|---|
| 0.60，前腿髖 | 241 | 173 | 105 | 36 |
| 0.84，前腿髖 | 114 | 45 | −23 | −92 |

即 H 在 0–0.45 BW 變動，前腿髖力矩改變 4–6 倍，甚至反號；膝力矩亦大幅變動。對比現有雙腳深蹲底點每側髖伸約 162 N·m（同 1.0 體重槓）。H = 0 時後腿髖出現約 −240 N·m 的屈髖需求，這在物理上不合理（後腳在凳上有摩擦與推力），所以 **H = 0 不能直接當預設**。

候選封閉假設（需教練確認，不得以驗證結果調整）：
1. H 取使總肌肉成本 Σa²/pref 最小（與現有肌肉分配的最小努力原則一致），受腳底摩擦錐 |H| ≤ μ·F_y 約束（μ 沿用專案估計 0.5 或另查）；示範原型以 Σ(M_hip² + M_knee²) 最小代替：前腳份額 0.60 時 H ≈ 0.41 BW，前／後髖 54／−54 N·m；0.84 時 H ≈ 0.10 BW，70／−70 N·m（此值僅為原型，未查證）。
2. H = 0（與現有伏地挺身「接觸點水平力為零」同型），但後腿屈髖力矩不合理，僅作敏感度端點。

前後腳垂直力份額由重心 Z 與兩腳壓力中心決定，可以由姿勢（骨盆前後位置）或一個教練參數（前腳份額）控制；文獻有保加利亞分腿蹲前腳平均約 84 %（Helme 2022，§9），**只能作校準／驗證候選，不用來設定預設**。

### 5.2 單腿站立的額狀面髖外展需求

骨盆置中（HAT 在骨盆中線）：支撐髖外展需求約 66.2 N·m（0.88 N·m/kg）；HAT 向支撐側偏移 2／4／6 cm：57.3／48.5／39.6 N·m。現有 `gmedFront`＋`gmedBack`＋`gmaxUpper` 的 F×力臂約 134 N·m（力長關係前）；模型缺臀小肌與闊筋膜張肌（見 §8），需求是否超載要在實作階段檢查，不能用此估量定論。

### 5.3 單臂啞鈴的 L5 額狀面力矩

站姿單手 10／20／30 kg、手距中線 0.28 m：27.5／54.9／82.4 N·m；對稱雙啞鈴為 0。腰背側屈肌群需求是新增的物理量（目前被 `trunkExt` 丟掉）。

### 5.4 對稱不變量（雙側求解器可重現半身結果）

兩接觸點垂直力解：由對稱深蹲姿勢的雙側求解得右腳 735.750 N，等於現有半身值 735.750 N。階段 0 的測試把這個檢查推廣到 69 項、各 5 個行程位置（§7）。

## 6. 推薦方案 C 的分階段實作

每個階段結束時 `node tests/regress.mjs` 必須 IDENTICAL（舊 72 項鍵不變）。單側條目一律以「**右側＝工作／前／支撐側**」求解，畫面換邊以 x 鏡像顯示（換邊不是新條目，不進 `catalog.set`；以鏡像不變量測試保證對稱）。

### 階段 0：基礎建設（不改數字）
1. `analyze` 拆成可重用的函式：`limbDemands(side)`（髖／膝／踝／肩／肘／肩帶）、`solveMuscles(dem, q, …)`（現有 4396–4440 的二次規劃）、回傳整理。回歸 IDENTICAL。
2. 力項加 `side: 'R'|'L'|'mid'`（預設 `undefined` = 舊語意）；`musMoment` 依側別過濾。肢體鏡像視圖 `limbView(pose, forces, 'L')`：把左側座標與力 x 取反，讓現有右手系肢體求解器直接重用（需處理前臂旋轉符號、`footUp`、`shPlane`）。
3. 三維軀幹方向 `trunkFrame3(Pc, {flex, side, rot})`；`side = rot = 0` 與舊 `trunkFrame` 位元相同。
4. 通用接觸求解器 `solveContacts(contacts, wrench, closure)`：垂直力、水平力封閉（成對水平力 H、外力水平分量依垂直份額分攤）、摩擦錐檢查、離地警告；3 點唯一解，2 點要求重心在連線上，≥ 4 點最小 Σ F² 並以 active set 處理非負。
5. **對稱不變量測試**：對 69 個可選項、5 個位置，把對稱姿勢送入雙側求解器（`pose.L = mirror(pose.R)`，雙側完整力），要求每側 `dem` 與 `mus.a` 與舊路徑差 < 1e-9；另有鏡像測試（左右互換結果鏡像）、平衡殘差（ΣF、ΣM = 0）測試。
- 量級：1 個大任務（重構 + 測試），約 1–2 天。

### 階段 1：單肢等效動作（單側腿伸／腿彎舉／腿推；單臂機械與固定把手）
- 物理與現有雙側動作一致（單肢、座椅承受身體），負重集中在一側；新增 `unilateral: { work: 'R' }` 旗標與 `workSide` 負重約定（取代 `/2`）。對側肢體不出力，畫面顯示為灰色／靜止。
- 同時建立：左右分色（`rig.js` 分別上色兩個 mesh）、左右數據欄、換邊鏡像。
- 驗證：與雙側動作每肢力矩對照（負重加倍時應等於；不是文獻校準）。
- 排除：座椅單臂划船／下拉會有軀幹軸旋需求，等階段 3。
- 量級：1–2 任務。

### 階段 2：分腿站姿（分腿蹲、固定位置弓步、保加利亞分腿蹲）
- 姿勢：前腳、後腳各自 `ik2`，後腳可在凳上；重心 Z 決定前後腳垂直份額；教練參數「前腳份額」（預設為示範選擇，需教練確認）與站距。
- 接觸：兩腳垂直力 + 水平成對力封閉（§5.1）；前後腿各自髖膝踝力矩與肌肉；軀幹仍對稱（槓在雙肩）不需要新軀幹肌肉。
- 額狀面：兩腳均接近各自髖下方，沿用「力線通過同側髖」封閉；若加入「腳位內外偏移」參數則需 §3.4 的額狀面求解（延後）。
- 動態弓步（行走、反向）是準靜態模型的邊界，另列。
- 量級：2 任務（姿勢＋接觸；肌肉與介面）。需要在此階段決定水平力封閉並由教練確認。

### 階段 3：軀幹三維與單臂／單側負重動作
- 新自由度 `trunkLat`、`trunkRot`；`dem.trunkLat`、`dem.trunkRot` 在 L5 取矩（`musMoment` 的 `trunk/upper/fore`）。
- 肌肉：`erec` 拆左右（`erecR/erecL`）；新增外斜肌、內斜肌（左右各一），因軸旋方向可分（對側外斜肌＋同側內斜肌同向旋轉）；腰方肌是否獨立為決策點：它與 `erec` 在側屈上缺少可分辨的力臂差異，依 T28 原則先併入 `erec` 的側屈功能，除非查到有出處的力臂（目前未查證）。力臂與最大力需要獨立的資料研究任務，且不得用排名調參。
- 動作：單臂啞鈴划船（手撐凳：三點支撐，垂直力唯一解）、單臂啞鈴肩推、單臂側平舉／彎舉變化、單臂滑輪划船／下拉／推（站姿單手鋼索水平力由雙腳依垂直份額分攤）、農夫走路（提箱）作驗證載體。
- 肩帶／肩：對側手臂的自重與位置進入軀幹平衡。
- 量級：3–4 任務，加 1 個資料研究任務（軀幹肌肉力臂與最大力）。

### 階段 4：單腿站立（單腿 RDL、登階、單腿蹲）
- 姿勢：支撐腿＋擺動腿（RDL 的擺動腿後伸、軀幹水平）；骨盆側移與側傾；額狀面重心置於支撐腳上方，技術參數「軀幹側傾」決定髖外展需求（§5.2）。
- 接觸：單腳單點，額狀面不能再用「力線通過髖」。
- 肌肉：評估是否加臀小肌與闊筋膜張肌；僅在 `hipExt/hipAbd` 力臂可分時加入（T28）。若不加，需在限制中說明髖外展容量偏低。
- 登階：靜態兩點（登階頂點、蹬離瞬間）與行程內準靜態插值，後腳推力成對封閉同 §5.1。
- 量級：2–3 任務，加髖外展肌肉參數研究。

### 階段 5：驗證與文件
- 用 §9 的研究建立固定容許差的比較（見 §7），每項單側動作加合理性與趨勢規則；更新 `limitations.md`、`methods.md`，移除「左右對稱」的限制句並改寫範圍。

## 7. 對既有項目、驗證與測試的影響

- **既有 72 項（69 可選＋3 規劃中）：**預設路徑不變。階段 0 的重構需讓 `tests/regress.mjs` 維持 IDENTICAL；新增單側動作只新增快照鍵。
- **旗標規則：**單側條目的 `LIFTS` 項帶 `bilateral: false`（或 `unilateral`）；`forcesOf`、`analyze` 看到旗標才走新路徑，舊 `L.ground / L.seated` 語意不變。
- **新增測試：**對稱等價（69 項）、鏡像不變量、靜力平衡殘差、封閉假設敏感度（H 與前腳份額掃描，輸出範圍不判定對錯）、`validate.mjs` 對兩側姿勢都要成立、`plausibility` 對單側條目的目標肌肉規則。
- **驗證工具：**`validate-sim.mjs` 需要 `side` 欄位指定比對前腳／後腳／支撐腿；容許差在看到模型值之前先固定；與專案原則一致，不得依比對結果調參。
- **UI／畫面：**左右分色、左右數據欄；換邊鏡像；單側動作的提示文字（`cues.js`）另寫。

## 8. 工作量與風險

| 項目 | 估計 | 風險 |
|---|---|---|
| 階段 0（重構＋接觸求解器＋不變量測試） | 1 個大任務 | 重構 `analyze` 約 280 行與 `forcesOf`；以回歸＋對稱等價測試防護 |
| 階段 1（單肢等效、UI 左右） | 1–2 任務 | 低 |
| 階段 2（分腿站姿） | 2 任務 | **水平力封閉**（§5.1）影響數倍；後腳在凳上的摩擦與推力沒有量測可套 |
| 階段 3（軀幹三維與單臂） | 3–4 任務＋1 資料任務 | 軀幹肌肉力臂與最大力沒有查證；腰方肌可能無法與 `erec` 區分；rig 的軀幹軸旋顯示（目前只有傾斜）要改成完整姿態 |
| 階段 4（單腿站立） | 2–3 任務＋資料任務 | 髖外展肌肉缺臀小肌與闊筋膜張肌，單腿站立可能產生類似肩帶的超載問題（`a > 1`）；準靜態對登階蹬離瞬間的限制 |
| 階段 5（驗證與文件） | 1 任務 | 文獻研究多為動態與 EMG，只能作趨勢與量級檢查 |
| 合計 | 約 11–14 個任務 | |

主要風險：(1) 靜力學不定性（水平力成對、四點支撐）只能以明示封閉假設處理，對結果有數倍影響；(2) 肌肉資料（軀幹、髖外展）不足，延續專案「肌肉活化是模型分配值」的限制；(3) 準靜態模型不含動態（登階、弓步、行走）；(4) 單側動作沒有雙腳驗證資料可沿用，文獻的量測定義（動態、EMG、不同負重）與模型不同，只能作方向與量級候選。

## 10. 需要教練／後續任務決定的事項

1. 分腿站姿的**水平力封閉假設**與前腳份額預設（§5.1）。
2. 軀幹肌肉粒度：腹斜肌、腰方肌是否各自獨立（資料研究後決定，T28 原則）。
3. 單腿站立是否加臀小肌與闊筋膜張肌（資料研究後決定）。
4. 單側動作換邊是否只做畫面鏡像（建議）。
5. 動態弓步、行走弓步是否留在範圍外（準靜態限制）。
